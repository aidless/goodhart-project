# chain-sort v2 设计: 状态可见性 2×2 对照实验

日期: 2026-10-12 夜 | 状态: **判读规则在运行前锁定** | 关联: KI-002, HANDOVER §13.20

## 0. 背景与动机

chain-sort 在批次 2 (qwen2.5:3b, 规则公开) step_acc=0.1168; 同族强模型
qwen2.5:7b 复测 0.0863 — **参数翻倍不升反降**, 「换强模型」腿否证。
两个候选解释:

- **H-track (状态追踪瓶颈)**: 模型无法在多步间携带序列状态 (每步都要求
  内部重放全部历史变换), 错误累积导致链断裂;
- **H-exec (规则执行瓶颈)**: 模型连单步变换 (rotate + 条件交换) 都执行不可靠。

区分这两个假设只需要一个操纵: **状态可见性**。v2 臂在 prompt 里直接给出
当前序列 (第 k 步提问时给出前 k 步折叠后的序列), 模型只需执行一次单步变换。

## 1. 设计: 2×2

| | 状态隐藏 (v1 prompt) | 状态可见 (v2 prompt) |
|---|---|---|
| qwen2.5:3b | 批次 2 已有: 0.1168 | 本实验新跑 |
| qwen2.5:7b | §13.20 已有: 0.0863 | 本实验新跑 |

- 同一批 30 个 chain-sort 任务 / 197 步 (schedules 不变, sha256 跨批一致);
- 同一判分器 (`Validator.check_step` 对 `truth_chain[k]`), 每臂
  `audit_replay` mismatch=0 为必要条件;
- temperature 0, 两臂唯一差异 = prompt 是否给出当前序列;
- **停止规则**: 每臂跑满 30 任务即停, 不中期窥视加跑。

## 2. 单向流保持声明

v2 的"当前序列"由 `run_etl.py` 内部用**公开字段折叠公开规则**得到
(`chain_sort_state(init_seq, k, sort_rule)`, 复用 `gen_tasks.apply_chain_sort`),
**不读 schedules.pkl, 不引用 truth_chain**。规则公开后真值链本就可由
公开信息重算 (KI-002 定案), v2 臂没有引入任何模型侧不可得的信息。
泄漏门禁 (v3.1 诱饵范式) 的 probe prompt 不经过 run_etl, 不受影响;
本实验前门禁对 (schedules, 3B) 已 PASS (批次 2, 日志归档), 对
(schedules, 7B) 已 PASS (§13.16), 判据文件未改, 不重跑。

## 3. 判读规则 (运行前锁定)

记 acc(v1, m) / acc(v2, m) 为模型 m 在 v1/v2 臂的步准确率 (同任务配对):

- **R1 (状态追踪瓶颈成立)**: acc(v2, 3B) ≥ 0.5 且 acc(v2,3B) ≥ 3×acc(v1,3B)
  → chain-sort 地板主要是状态追踪问题; 修复方向 = 任务设计 (状态可见/
  逐步反馈), 不必换更强模型。
- **R2 (规则执行瓶颈成立)**: acc(v2, 3B) ≤ 0.2 (单步变换也做不对)
  → 修复方向 = 单步执行本身 (更强模型 / 分步教学 / 更简规则), 状态可见
  不解决。
- **R3 (混合)**: 其余情形 → 两个成分都存在, 以 (v2−v1) 差值归因主成分,
  并报 7B 交互项: 若 7B 的 (v2−v1) 显著大于 3B 的, 说明容量放大了
  状态可见性的收益。

正式判读用**点估计 + 方向**, 不做显著性检验 (n=197 步/臂, 二项抽样
误差 ~±0.05, 判读阈值 0.5/3× 远超该噪声); 所有结果标 [exploratory]
(事后设计, 非预注册库中的 C.2 类实验)。

## 4. 预期与价值

无论哪个分支都有信息量: R1 → chain-sort 改设计的具体形式确定
(显示状态或逐步反馈, 而不是重写规则); R2 → KI-002 的"任务设计"结论
进一步收窄为"执行原语"; R3 → 拆分两个成分的相对贡献。
结果直接喂给 Q2 (重锚定假说的因果版) 与 Q4 (链长外推前置)。

## 5. Q4 扩样本规格 (同批设计, 独立执行)

Q4 (短链→长链外推) 本批不可判的原因: 逐 k 样本 4–30, 无可靠 k 趋势
(R²≈0), stateful 留出检验退化。扩样本规格 (待 v2 实验收口后另行执行,
不与本实验混批):

1. **新任务集**: chain-sort/stateful-calc 各生成 n_steps ∈ {2,4,6,8,10,12}
   × 10 重复 = 120 任务 (独立 schedules 文件, 不动主 90 任务);
2. **臂**: 规则公开 + 状态可见 (v2 语义, 由 R1/R2 结果定夺是否需要
   状态隐藏臂);
3. **判据**: 拟合 log(acc) ~ k 的斜率在 n_steps ≤ 6 段训练、> 6 段留出,
   留出段平均绝对误差 < 0.05 才判"可外推"; 需要 ≥ 3 个模型重复方向
   一致才算稳健;
4. **前置**: 依赖本实验 R 判读 (若 R2 成立, 长链外推的基线任务族
   需先换)。

## 6. 结果与判读 (2026-10-12 晚, 运行后补记)

2×2 全部四格 (chain-sort, 30 任务 / 197 步每臂, temperature 0,
audit_replay mismatch=0 ×4):

| step_acc | v1 状态隐藏 | v2 状态可见 |
|---|---|---|
| qwen2.5:3b | 0.1168 | 0.1015 |
| qwen2.5:7b | 0.0863 | 0.0609 |

- **R2 判读成立**: acc(v2, 3B) = 0.1015 ≤ 0.2 — 状态可见不解决
  chain-sort 地板; 单步变换执行本身即是瓶颈。
- R1 否证 (0.1015 ≪ 0.5, 且 v2−v1 ≈ 0); R3 的交互项不存在:
  7B 在两臂均 ≤ 3B, 容量没有放大任何收益。
- **定性观察 (post-hoc 注记, 冒烟即见)**: v2 prompt 下两模型常输出
  当前序列的**全排序** (asc/desc 混用, 与规则名一致或相反), 而非
  rotate+条件交换的机械单步 — "sort_rule" 被语义理解为"排序"而非
  状态机步骤; 输出确为当前序列的排列, 说明状态被正确使用。
- **修复方向收窄**: 状态可见 ✗ (本实验), 更大容量 ✗ (§13.20+本实验),
  剩余候选 = 执行原语重构: 单步 worked example / 分解式指令 /
  更简变换规则。归 KI-002。
